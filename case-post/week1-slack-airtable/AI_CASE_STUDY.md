# AI가 한 설정을 AI로 검증했다: 오픈클로 슬랙·에어테이블 연결에서 찾은 구멍들

## 소개

24기 스터디 1주차 수업자료 링크를 슬랙에서 제 봇 필로에게 주고 "우리한테 필요한 내용 조치해줘"라고 시켰어요. 필로는 "조치 끝났습니다"라고 보고했고, 그 아래에는 600초 무응답 경고가 붙어 있었습니다. 그 보고를 Claude Code에 그대로 가져가 하나씩 대조했더니, 필로가 한 일은 맞았지만 수업자료를 읽은 방향이 달랐고, 그 뒤 설정 과정에서도 말없이 바뀐 것과 새어 나간 것이 나왔어요. 이 글은 그 검증 기록입니다.

**바쁘시면 이것만 읽어도 돼요**
- 도구와 목표: 오픈클로(OpenClaw) 봇을 24기 슬랙에 두 번째 계정으로 붙이고 에어테이블 스킬까지 연결. 검증과 수정은 Claude Code로
- 핵심 해결: 봇의 보고를 파일·로그·API로 대조하고, 설정을 바꿀 때마다 "바꾸려던 것 말고 뭐가 같이 바뀌었나"를 확인
- 가장 인상적이었던 순간: 새 슬랙을 붙였을 뿐인데 원래 슬랙의 연결이 말없이 다른 에이전트로 넘어가 있던 것
- 교훈 하나: "조치 끝났습니다"는 보고이지 확인이 아니에요. 검증하던 AI도 실수했습니다

**이런 분들께 도움돼요**
- 오늘 1주차 수업을 듣고 슬랙·에어테이블 연결을 따라 하는 24기 스터디원, 특히 이미 다른 슬랙에 봇을 붙여 둔 분
- 봇에게 "설정 좀 고쳐줘"를 맡기기 시작했고, 그 보고를 어디까지 믿어야 할지 고민인 분
- 토큰을 AI와 함께 다룰 때 어디서 새는지 궁금한 분

### 문제 상황

저는 '생각하는 글밭'이라는 교육 프로젝트에서 AI 캐릭터 10명을 오픈클로로 돌리고 있어요. 오늘 낮에 헤르메스에서 오픈클로로 이사를 마쳤고, 슬랙 워크스페이스 "질문연구소mini"에는 이미 봇이 붙어 있었습니다.

저녁 9시 수업 전에 1주차 수업자료를 미리 반영해 두고 싶어서, 코디네이터 캐릭터인 필로에게 슬랙으로 시켰어요. 필로의 보고는 이렇게 시작했습니다.

```
조치 끝났습니다. 대조 결과 보고합니다.

내가 지금 고친 것 3개
joinIntro: false — 이게 실제 구멍이었습니다. 우리는 이 값이 아예 없었고 기본값이 true라,
어떤 채널에 초대되든 봇이 최근 대화 100개를 읽고 혼자 자기소개를 올리는 상태였습니다. 껐습니다.
...
가장 큰 문제 — 은쌤이 직접 해야 합니다
우리 슬랙 앱 봇 스코프가 7개뿐입니다. 수업자료 매니페스트는 24개고요.
```

그리고 보고 맨 끝에는 이 경고가 붙어 있었어요.

```

```

"조치 끝났습니다"와 "effects may be partial"이 한 화면에 같이 있었습니다. 뭐가 됐고 뭐가 안 됐는지 제가 판단할 수 없었어요.

## 진행 방법

**사용한 도구**
- Claude Code (Fable 5.1) — 필로 보고 검증, 설정 점검, 스크립트 수정
- Claude in Chrome — 슬랙 앱 설정 화면 조작 (설치 허용과 토큰 발급은 제가 직접)
- OpenClaw 2026.9.6 — 에이전트 런타임. 필로는 여기서 claude-opus-5로 동작
- Slack 앱 2개(소켓 모드), Airtable + nodak-airtable 스킬

### 필로의 보고를 파일과 로그로 대조했더니

Claude Code는 필로의 말을 믿고 시작하지 않았어요. 설정 파일을 백업과 비교하고, 게이트웨이 로그를 읽고, 필로의 세션 기록까지 열어 봤습니다. 결과는 이랬어요.

- **맞은 것**: 필로가 했다는 조치 3개는 전부 실제로 반영돼 있었어요. 설정 파일은 백업과 딱 한 줄만 달랐습니다.
- **필요 없던 부탁**: 필로는 "재시작은 제 권한 밖이라 은쌤이 한 번 눌러주세요"라고 했는데, 로그를 보니 게이트웨이가 이미 재시작 없이 그 설정을 읽어 들인 뒤였어요.
- **워치독 경고의 정체**: 필로가 설정을 고친 바로 그 턴에서 점검 명령(`openclaw doctor`)을 돌렸고, 이게 3분을 넘기면서 꼬였습니다. 두 답변은 모두 슬랙에 전달된 뒤였고 잃은 작업은 없었어요. 게이트웨이가 왜 턴이 끝난 걸 못 알아챘는지 직접 원인은 확인하지 못했습니다.
- **방향이 달랐던 것**: 수업자료의 슬랙 단계는 "기존 앱을 고쳐라"가 아니라 "24기 슬랙에 새 앱을 만들어 새 계정으로 붙여라"였어요. 설정 다섯 줄도 그 새 계정 안에만 넣으라고 적혀 있었습니다. 필로는 이걸 우리 기존 워크스페이스와 비교해서 "스코프가 부족하다", "allowBots를 켤까요?"라고 물었던 거예요.
- **작은 숫자**: 수업자료 매니페스트의 스코프를 세어 보니 23개였어요. 필로는 24개라고 했습니다.
- **새로 나온 것**: 필로가 설정을 점검하면서 슬랙 토큰 두 개를 가리지 않고 출력해서, 자기 세션 기록 파일에 평문으로 남겨 두었어요.

필로가 거짓말을 한 건 아니에요. 한 일은 정확히 보고했습니다. 다만 "무엇을 해야 하는지"를 읽는 데서 어긋났고, 그건 보고서만 봐서는 알 수 없었어요.

### 매니페스트를 넣었는데 권한이 0개였다

24기 슬랙에 새 앱을 만드는 건 Claude in Chrome으로 진행했어요. 여기서 두 번 멈췄습니다.

첫 번째는 Claude Code 쪽 안전장치였어요. 권한 23개를 요청하는 매니페스트를 넣으려는 순간 자동 검사에 걸려서, Claude Code가 멈추고 저에게 물었습니다. 제가 이렇게 답한 뒤에야 진행됐어요.

```
매니페스트 넣어도 된다.
```

두 번째는 슬랙 화면이었어요. 편집기에 매니페스트가 들어간 것처럼 보였는데, 다음 화면의 미리보기에는 "권한 0개, 이벤트 0개"라고 나왔습니다. 글자는 화면에 들어갔지만 슬랙이 입력으로 인식하지 못한 거였어요. 뒤로 가서 붙여넣기 방식으로 다시 넣었더니 23개와 15개로 바뀌었습니다.

미리보기 숫자를 확인하지 않았다면 모르고 넘어갈 뻔했어요. Create와 설치 허용, 토큰 발급은 제가 직접 눌렀습니다.

### 새 슬랙을 붙였더니 원래 슬랙이 다른 에이전트로 가 있었다 — 핵심 전환

토큰 두 개를 받고 터미널에서 `openclaw channels add`를 실행했어요. 수업자료가 강조한 대로 "Add a new account"를 골랐고, 마지막에 `Channels updated.`가 떴습니다.

```
끝났어
```

제가 이렇게 말하자 Claude Code는 "새 계정이 붙었는지"만 보지 않고, 기존 계정이 그대로인지부터 확인했어요. 기존 토큰은 백업과 동일했고 채널 목록도 그대로였습니다. 그런데 라우팅 규칙이 달라져 있었어요.

- 전: 슬랙으로 온 말은 전부 필로에게
- 후: **24기 계정**으로 온 말만 필로에게

마법사가 기존 규칙을 새 계정 전용으로 바꿔 버린 거예요. 그대로 뒀다면 원래 워크스페이스의 필로 채널과 DM은 필로가 아니라 기본 에이전트가 받게 됩니다. 에러도 경고도 없었어요. 아래 한 줄로 되살렸습니다.

```
openclaw agents bind --agent philo --bind slack:default
```

그다음 수업자료의 설정 다섯 줄을 새 계정 안에만 넣었어요. 기존 워크스페이스는 등록한 채널에서만 동작하는 좁은 설정을 유지했습니다.

```
"dmPolicy": "pairing",
"groupPolicy": "open",
"allowBots": true,
"replyToMode": "all",
"joinIntro": false
```

### "스레드 답글이 오지 않았어"

DM 승인까지 마치고 #봇-실험실에 필로를 초대해 말을 걸었는데 답이 안 보였어요.

```
필로가 초대는 되었는데, 스레드 답글이 오지 않았어. #봇-실험실
```

Claude Code가 로그와 슬랙 스레드를 조회해 보니 답글은 이미 달려 있었습니다. 제 메시지 15초 뒤였어요. 스레드 답글은 채널 본문에 따로 안 보이고 메시지 아래 "댓글 1개" 링크 안에 있어서 제가 못 본 거였습니다. 이번에는 제 쪽이 검증 대상이었네요.

### 에어테이블 토큰이 대화에 찍혔다

에어테이블은 베이스를 만들고 토큰을 발급해 스킬 폴더의 `.env`에 넣으면 끝나요. 수업자료는 봇 DM으로 토큰을 보내라고 하는데, 그러면 토큰이 슬랙 메시지와 봇의 세션 기록에 남아서 저는 터미널에서 직접 넣기로 했습니다.

제가 토큰을 저장한 뒤 Claude Code가 "값은 보지 않고 형태만 확인하겠다"며 확인 명령을 돌렸는데, 그 출력에 토큰 전체가 찍혔어요. 원인은 두 가지가 겹친 거였습니다.

- 제가 저장한 줄에 `AIRTABLE_API_KEY=`라는 이름표가 빠져 있었어요.
- Claude Code의 확인 명령은 "이름에 KEY가 들어간 줄만 가린다"는 방식이었어요. 이름표가 없는 줄은 가릴 대상으로 보지 않고 통째로 출력했습니다.

Claude Code는 바로 무슨 일이 있었는지 설명하고 재발급을 권했어요. 저는 새 토큰을 발급하고 예전 것을 지웠습니다. 그 뒤 확인은 "가릴 줄을 고르는" 방식이 아니라 "출력해도 되는 줄만 고르는" 방식으로 바뀌었어요. 결과는 이렇게 나왔습니다.

```
AIRTABLE_BASE_ID=(베이스 ID)
AIRTABLE_API_KEY = <hidden> starts_with_pat=yes dots=1 len=82 placeholder=no spaces=no
```

그리고 슬랙에서 필로에게 시켜 에어테이블에 한 줄이 추가되는 것까지 확인했어요.

### 다시 돌리면 오늘 한 일이 지워지는 스크립트

마지막으로 필로의 규칙 파일에 "설정을 고친 턴에서는 점검 명령을 돌리지 않는다"를 추가했어요. 그 과정에서 Claude Code가 낮에 만든 설치 스크립트를 다시 읽다가 문제를 하나 더 찾았습니다. 주석에는 "재실행해도 안전하다"고 적혀 있는데, 실제로는 돌릴 때마다 캐릭터들의 파일을 새로 덮어쓰고 있었어요. 다시 돌리면 오늘 넣은 슬랙 ID와 규칙이 전부 사라집니다.

```
setup-agents.sh 덮어쓰기 문제 고쳐줘
```

파일이 없을 때만 만들도록 고쳤고, 실제 파일을 건드리지 않게 임시 폴더에서 시험했어요. 기존 파일 40개에 변화가 없고, 두 번 돌려도 두 번째는 아무것도 바꾸지 않는 것을 확인했습니다.

## 결과와 배운 점

### 확인된 결과

- Before: 필로가 슬랙 워크스페이스 한 곳에만 연결 → After: 기존 워크스페이스와 24기 슬랙 두 곳에 연결, 둘 다 `running, connected` (근거: `openclaw channels status`)
- Before: 계정 추가 직후 기존 슬랙이 기본 에이전트로 라우팅 → After: 텔레그램·24기 슬랙·기존 슬랙 세 경로 모두 필로로 (근거: `openclaw agents list --bindings`)
- Before: 에어테이블 연결 없음 → After: 스킬이 베이스의 테이블을 읽고, 슬랙에서 한 줄 추가 (근거: 스키마 동기화 출력, 한 줄 추가는 제가 에어테이블에서 확인)
- Before: 기존 슬랙 앱 스코프 7개·이벤트 3개 → After: 스코프 24개·이벤트 13개, 토큰은 그대로 (근거: 슬랙 API 응답의 스코프 목록)
- Before: 설치 스크립트를 다시 돌리면 캐릭터 파일 덮어씀 → After: 있으면 건너뜀 (근거: 임시 폴더 시험, 커밋 `323baf6`)
- 걸린 시간: 첫 요청부터 마무리까지 약 2시간 15분 (근거: 세션 기록 19:48~22:04)

### 시행착오

이날 "됐다"는 신호가 실제와 달랐던 순간을 모아 보면 이래요.

1. 필로의 "조치 끝났습니다" → 한 일은 맞았지만 수업자료가 요구한 일과는 달랐음
2. 슬랙 편집기에 들어간 매니페스트 → 미리보기에서는 권한 0개
3. 마법사의 `Channels updated.` → 기존 라우팅이 같이 바뀜
4. "스레드 답글이 오지 않았어" → 15초 뒤에 와 있었음
5. "값은 보지 않고 확인하겠다" → 토큰이 통째로 출력됨
6. 스크립트 주석 "재실행해도 안전하다" → 실제로는 덮어씀

제가 가장 기억에 남는 건 앞의 1, 3, 5번이에요. 필로가 끝났다고 해서 끝난 줄 알았는데 수업자료를 다르게 읽고 있었던 것, 새 슬랙을 붙였을 뿐인데 원래 슬랙의 연결이 말없이 바뀌어 있었던 것, 그리고 검증하던 AI도 토큰을 노출하는 실수를 한다는 것.

### 꿀팁

1. **봇의 보고는 "한 일"과 "해야 했던 일"을 따로 확인하세요.** 한 일은 파일과 로그로 대조하면 돼요. 해야 했던 일은 원문(수업자료)을 다시 읽어야 보입니다.
2. **설정을 하나 바꿨으면 바꾸려던 것 말고 뭐가 달라졌는지 보세요.** 백업과 비교하는 게 제일 빨라요. 이번엔 계정을 추가했는데 라우팅이 같이 바뀌었습니다.
3. **이미 슬랙에 봇이 있는 분은 계정 추가 뒤에 `openclaw agents list --bindings`를 꼭 보세요.** 기존 슬랙이 목록에서 빠져 있으면 `openclaw agents bind --agent 내봇ID --bind slack:default`.
4. **비밀값을 확인할 때는 "가릴 것"이 아니라 "보여도 되는 것"을 고르세요.** 가릴 줄을 고르는 방식은 예상 못 한 모양의 줄을 그대로 내보냅니다.
5. **토큰은 봇 DM 대신 터미널에서 파일에 직접 넣는 방법도 있어요.** 슬랙 메시지와 세션 기록에 남지 않습니다.
6. **스레드 답글은 "댓글 1개" 링크 안에 있어요.** 답이 안 온 것 같으면 그 링크부터 눌러 보세요.

### 이렇게 하면 안 돼요

1. 봇에게 설정을 고치게 한 그 턴에서 점검 명령이나 재시작까지 시키지 마세요. 저희는 600초 무응답 경고로 끝났습니다.
2. `openclaw channels add`의 계정 선택에서 기존 계정에 Enter를 치지 마세요. 수업자료에도 있는 경고예요. 기존 토큰이 덮어써집니다.
3. 토큰이 대화에 한 번이라도 보였다면 "로컬이니까 괜찮겠지" 하고 넘기지 마세요. 재발급은 1분이면 됩니다.

### 다른 업무에 적용한다면

AI에게 일을 맡기고 다른 AI로 그 결과를 검증하는 구조는 설정 작업 말고도 쓸 수 있을 것 같아요. 예를 들어 봇이 쓴 글이나 만든 표를 다른 세션에서 원문과 대조하게 하는 식으로요. 다만 이번에 본 것처럼 검증하는 쪽도 틀릴 수 있으니, 마지막 확인은 사람이 눌러야 한다는 점은 같을 거예요. 아직 해 본 것은 아닙니다.

### 도움이 필요한 부분

24기 슬랙에서 봇 이름이 안 바뀌어요. 앱 설정의 Display Name (Bot Name)에는 `필로`로 저장돼 있는데, 슬랙에는 계속 `philo`로 나옵니다. 재설치도 해 보고 이름을 바꿨다 되돌려도 봤는데 그대로예요. 수업자료는 이 이름 변경을 설치 전에 하도록 되어 있고 저는 설치 후에 했습니다. 같은 상황을 겪으셨거나 해결하신 분이 계시면 알려 주세요.
