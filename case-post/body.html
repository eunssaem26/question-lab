소개

스터디에서 받은 가이드대로 오픈클로(OpenClaw)를 설치하는 데는 30분이면 충분했어요. 문제는 그 다음이었습니다. 헤르메스에서 운영하던 AI 캐릭터 10명을 옮기고, 텔레그램과 슬랙을 다시 붙이고, 클로드 Max 구독을 연결하고 나서야 "설치됐다"와 "제대로 돌아간다"가 얼마나 다른지 알게 됐어요. 이 글은 설치 다음에 만난 문제 다섯 개와, 그걸 Claude Code와 함께 하나씩 잡아낸 기록입니다.

바쁘시면 이것만 읽어도 돼요

  • 도구와 목표: Claude Code로 헤르메스 → 오픈클로 이전, 캐릭터 10명 + 텔레그램 + 슬랙 + 클로드 Max 연결
  • 핵심 해결: 자동 마이그레이션 대신 설치 스크립트, 성격 파일은 심볼릭 링크 대신 복사본 자동 동기화
  • 가장 인상적이었던 순간: 봇이 규칙을 어기고 문항을 직접 만들어 버린 걸 보고 "성격 파일이 안 읽혔구나"를 잡아낸 것
  • 교훈 하나: 설치 가이드의 체크리스트가 끝나는 지점에서 진짜 점검이 시작된다

이런 분들께 도움돼요

  • 오늘 스터디에서 오픈클로를 막 설치했고, "다음에 뭘 확인해야 하지?"가 궁금한 분
  • 텔레그램이나 슬랙에 AI 봇을 붙였는데 답이 느리거나, 두 채널을 같이 쓰면 대화가 어떻게 나뉘는지 궁금한 분
  • 헤르메스나 NanoClaw 같은 다른 에이전트 런타임을 쓰다가 갈아타려는 분

문제 상황

저는 '생각하는 글밭'이라는 교육 프로젝트에서 AI 캐릭터 10명(필로·별쌤·책쌤·글쌤·은쌤·깐쌤·호기·영쌤·밭피디·가드너)을 헤르메스라는 에이전트 런타임으로 돌리고 있었어요. 각자 성격 파일(SOUL.md)이 있고, 텔레그램 봇과 슬랙 채널에 연결되어 있었습니다.

바꾸게 된 계기는 모델 비용이었어요. 코덱스를 붙여 쓰려 했는데 Plus 요금제로는 한도에 금방 걸렸고(실제로 이날 작업 중에도 "usage limit" 에러가 찍혔습니다), 오픈클로는 이미 쓰고 있는 클로드 Max 구독을 그대로 연결해 쓸 수 있다는 얘기를 들었거든요. 마침 24기 스터디에서 오픈클로 설치 가이드를 받은 날이었습니다.

그런데 제 상황은 "새로 설치"가 아니라 "이사"였어요. 옮겨야 할 프로필이 10개, 재사용할 토큰이 텔레그램 하나와 슬랙 두 개, 그리고 헤르메스에 붙어 있던 웹 화면까지. 가이드에는 없는 일이었습니다.

Claude Code에게 보낸 첫 요청은 이랬어요.

오픈클로를 다시 설치했어. 코덱스를 연결할까 했는데, 플러스는 용량이 너무 작아서 리밋 걸려서 안될 듯. 오픈클로에 클로드 구독 연결해서 잘 쓰더라고. 우리도 오픈클로 쓰자. 헤르메스에서 이전작업도 해야 하고, 슬랙이랑 텔레그램 연결도 다시 하자.

진행 방법

사용한 도구

  • Claude Code (Fable 5.1) — 상태 파악, 스크립트 작성, 설정 변경, 로그 분석 전부
  • OpenClaw 2026.9.6 — 에이전트 런타임. 게이트웨이가 macOS에 상주
  • 클로드 Max 구독 — "Claude CLI 재사용" 방식으로 연결, 모델은 claude-opus-5
  • 텔레그램 봇, 슬랙 앱(소켓 모드) — 기존 토큰 재사용
  • Claude in Chrome — 웹 화면 동작 검증

자동 마이그레이션 명령을 돌려보고, 버렸다

오픈클로에는 헤르메스에서 옮겨오는 migrate 명령이 있어요. Claude Code가 먼저 미리보기(dry-run)로 돌려봤더니 120개 항목이 나왔는데, 대부분이 범용 스킬을 복사하는 것이었고 정작 제가 원하는 "캐릭터 10명을 각각 독립 에이전트로"는 그 명령의 범위가 아니었습니다.

그래서 자동 이전은 쓰지 않고, 설치 스크립트를 하나 짰어요. 캐릭터마다 작업 폴더를 만들고, 정체성·규칙·아바타 파일을 넣고, 오픈클로에 에이전트로 등록하는 걸 10번 반복하는 스크립트입니다. 2분 만에 10명이 등록됐습니다. 이날 배운 첫 번째 것은 "도구가 제공하는 마이그레이션이 내 상황에 맞는지 미리보기로 먼저 본다"였어요.

텔레그램과 슬랙은 기존 토큰으로 5분

채널 연결은 허무할 정도로 빨랐어요. 헤르메스 설정 파일에 남아 있던 텔레그램 봇 토큰, 그 전 세대인 NanoClaw 백업 폴더에 있던 슬랙 토큰 두 개를 그대로 넣었더니 상태 점검에서 둘 다 "works"가 떴습니다.

한 가지 주의할 점이 있었어요. 같은 텔레그램 토큰을 헤르메스와 오픈클로가 동시에 쓰면 충돌하니까, 헤르메스 게이트웨이를 멈추고 자동 시작 설정을 꺼 두었습니다. 데이터는 지우지 않고 그대로 뒀어요.

클로드 구독 연결은 제가 직접 한 줄

클로드 구독 연결은 브라우저 확인이 필요한 명령이라 Claude Code가 대신 못 하고, 제가 터미널에 직접 쳐야 했어요. 처음엔 이런 에러가 났습니다.

! openclaw models auth login --provider anthropic --method cli --set-default
→ Multiple agents are configured, but the model command has no explicit owner. Pass --agent <id>.

에이전트가 여러 명이라 누구 것인지 지정하라는 뜻이었어요. --agent philo를 붙이니 바로 통과됐고, 확인해 보니 설정이 전역에 잡혀서 10명이 같이 쓰게 되어 있었습니다. 토큰을 복사하는 게 아니라 이미 로그인된 Claude 명령줄을 재사용하는 방식이라, 오픈클로 쪽에 인증 정보가 따로 저장되지 않는 점이 마음에 들었어요.

필로가 문항을 직접 만들어 버렸다 — 핵심 전환

여기부터가 진짜였어요. 연결이 다 됐으니 코디네이터 캐릭터인 필로에게 테스트를 던졌습니다. 필로의 규칙은 "문항을 직접 만들지 않고 담당 캐릭터에게 배정한다"예요. 그런데 "문항 5개 지금 바로 만들어줘"라고 하니 문항 5개를 직접 만들어 버렸습니다.

성격 파일이 안 읽힌 거예요. Claude Code가 로그와 오픈클로 소스를 뒤져 원인을 찾았는데, 오픈클로는 작업 폴더의 부트스트랩 파일이 심볼릭 링크면 하드코딩으로 거부하고 있었습니다. 저는 성격 파일 원본을 저장소 한 곳에 두고 각 캐릭터 폴더에는 링크만 걸어 뒀거든요. 헤르메스에선 됐던 방식이 오픈클로에선 조용히 무시된 겁니다. 에러도 안 나고, 그냥 규칙 없는 봇이 되어 있었어요.

[[IMG2]]

해결은 "원본은 저장소, 캐릭터 폴더에는 복사본"으로 바꾸고, 원본을 고치면 복사본을 자동으로 맞춰 주는 동기화 스크립트를 커밋 훅에 연결한 것이었어요. 다시 테스트하니 필로가 문항을 만들지 않고 "책쌤 → 별쌤 → 깐쌤 → 은쌤" 순서로 요청을 분해했습니다. 이때부터 "연결됨"이 아니라 "규칙대로 행동함"을 확인 기준으로 삼게 됐어요.

스터디 자료와 대조했더니 남아 있던 것

설치가 다 끝난 뒤 스터디 설치 가이드의 체크리스트 12항목과 하나씩 대조했어요.

오늘 스터디자료야. 이 자료 보고 모든 내용 잘 반영되었는지 확인해줘.

10개는 반영되어 있었고, 2개(텔레그램 첫 수신, 슬랙 DM)는 제가 메시지를 보내야 확인 가능했어요. 그런데 대조 과정에서 가이드대로 설치하면 안 남는 게 우리 환경에 남아 있는 걸 발견했습니다. 처음에 시도했던 코덱스 플러그인 잔재가 켜져 있어서 코덱스 프로세스가 8개나 떠 있었어요. 플러그인을 끄고 설정을 지우니 0개가 됐고, doctor 경고도 사라졌습니다. 가이드에서 "토큰이 터미널 기록에 남을 수 있다"고 경고한 항목도 확인했는데, 다행히 남아 있지 않았어요.

텔레그램 답장이 163초 걸린 이유

마지막으로 제가 텔레그램과 슬랙에 실제 메시지를 보내 봤어요.

텔레그램이랑 슬랙에 메시지 보냈어, 확인해줘

둘 다 답장은 왔는데, 슬랙은 12초, 텔레그램은 163초였습니다. 원인이 재미있었어요. 텔레그램 DM은 필로의 "메인 세션" 하나를 계속 쓰는데, 그날 초반에 Claude Code가 세션을 지정하지 않고 돌린 테스트들이 전부 거기 쌓여서 이미 10만 토큰이 되어 있었던 거예요. 제 메시지 하나에 그 맥락을 통째로 이어받느라 오래 걸린 거죠. 슬랙은 스레드마다 새 세션이라 가벼웠고요.

메인 세션은 명령줄로 지울 수 없게 되어 있어서, 텔레그램에서 /new를 보내 새 세션으로 시작하는 게 정석이었습니다. 그리고 앞으로 명령줄 테스트는 항상 세션 ID를 따로 붙이기로 했어요.

웹 화면(캐릭터를 클릭해 대화하는 강의 시연용 페이지)도 헤르메스 대신 오픈클로 게이트웨이에 직접 붙였는데, 브라우저는 기기 인증 서명이 필요해서 첫 접속 때 페어링을 승인해 주는 절차가 추가됐어요. 이 부분은 개발 이야기라 여기서는 줄입니다.

사용한 프롬프트 전문

이날 Claude Code에게 보낸 요청은 위에 나온 것들이 전부예요. 긴 프롬프트는 없었고, 상황을 있는 그대로 말한 짧은 문장들이었습니다. 다시 쓴다면 첫 요청은 이렇게 보내겠어요.

오픈클로를 설치했어. 헤르메스에서 쓰던 캐릭터 프로필 N개를 각각 독립 에이전트로 옮기고, 기존 텔레그램·슬랙 토큰을 재사용해서 연결해줘. 모델은 클로드 Max 구독을 Claude CLI 재사용 방식으로 붙이고 싶어.
먼저 현재 상태(설치 버전, 인증 프로필, 기존 토큰 위치)를 확인하고, 자동 마이그레이션 명령은 미리보기로만 돌려서 내 상황에 맞는지 알려줘.
연결이 끝나면 "연결됨"이 아니라 캐릭터가 자기 규칙대로 행동하는지까지 테스트해줘. 테스트할 때는 내 채널 세션을 쓰지 말고 세션 ID를 따로 붙여줘.

결과와 배운 점

확인된 결과

  • 캐릭터 10명이 오픈클로 독립 에이전트로 등록 (근거: 에이전트 목록 출력, 설치 스크립트 커밋)
  • 텔레그램·슬랙 연결, 실제 수신과 답장 확인 (근거: 채널 상태 점검 "works", 수신 로그)
  • 슬랙 채널별로 다른 캐릭터가 응답: 글쌤 채널은 글쌤, 책쌤 채널은 책쌤, 별쌤 채널은 별쌤, 나머지는 필로 (근거: 바인딩 설정 5개 적용 로그)
  • 클로드 Max 구독으로 10명 공유, 코덱스 프로세스 8개 → 0개 (근거: 프로세스 수 확인)
  • 필로 경계 테스트 통과, 웹 화면에서 깐쌤·호기·책쌤 경계 테스트 3건 통과 (근거: 응답 내용 확인)
  • 첫 응답 속도: 콜드스타트 약 35초, 이후 6~12초 (근거: 명령줄 타이머와 로그의 밀리초 기록)
  • 시간: 첫 요청 13:51 → 마무리 16:23. 설치 자체보다 검증과 수정이 훨씬 길었어요.

시행착오

  • 성격 파일이 조용히 무시됨 → 가설: 심볼릭 링크 문제 → 소스에서 링크 거부 코드 확인 → 복사본 + 자동 동기화로 수정
  • 텔레그램 답장 163초 → 가설: 모델이 느린가? → 로그의 세션 키와 토큰 수 확인 → 테스트가 메인 세션을 오염시킨 것. /new와 세션 ID 분리로 해결
  • 첫 스모크 테스트가 코덱스 한도 에러 → 게이트웨이 재시작으로 모델 라우팅 갱신
  • 호기 첫 답이 42초 → 메모리 벡터검색이 코덱스 임베딩으로 가서 30초 타임아웃 → 우리 메모리는 짧은 포인터뿐이라 벡터검색 자체를 끔 → 6.5초
  • 설정 변경이 반영 안 됨 → "플러그인이 작업을 붙들고 있다" 메시지 → 게이트웨이 재시작이 답

꿀팁

  1. "연결됨"과 "규칙대로 행동함"은 다른 상태예요. 채널 상태가 works여도 성격 파일이 안 읽혔을 수 있어요. 규칙을 일부러 어기게 하는 질문 하나를 테스트로 준비해 두세요.
  2. 자동 마이그레이션은 미리보기부터. 도구가 옮겨 주는 것과 내가 옮기고 싶은 것이 다를 수 있어요.
  3. 테스트는 내 채널 세션과 분리해서. 명령줄로 테스트할 때 세션 ID를 따로 주지 않으면 텔레그램 대화 세션에 쌓여서 나중에 느려져요.
  4. 설치 가이드 체크리스트가 끝나면 한 번 더 대조하세요. 가이드대로 했으면 없어야 할 것(이전에 시도한 플러그인 잔재 등)이 남아 있을 수 있어요.
  5. 같은 봇 토큰을 두 런타임이 동시에 쓰면 안 돼요. 옛 런타임은 멈추고 자동 시작을 끄되, 데이터는 지우지 마세요.

이렇게 하면 안 돼요

  1. 성격 파일을 심볼릭 링크로 걸어 두기 — 오픈클로는 에러 없이 무시합니다.
  2. 메인 세션에서 이것저것 실험하기 — 지울 수 없는 세션이라 오염되면 /new로 새로 시작해야 해요.
  3. 슬랙 그룹 정책을 "open"으로 두고 캐릭터를 여러 명 붙이기 — 봇이 들어간 모든 채널에서 반응합니다. 채널별로 캐릭터를 지정했다면 allowlist가 맞아요.

슬랙과 텔레그램을 같이 쓰면 헷갈리지 않나요

작업 끝에 제가 물어본 질문이에요. 답은 "헷갈리지 않는데, 그 이유가 서로 아예 모르기 때문"이었습니다. 오픈클로는 대화를 "채널 × 상대 × 스레드" 단위 세션으로 나눠요. 텔레그램에서 필로에게 시킨 일을 슬랙의 필로는 모릅니다. 같은 캐릭터인데 기억이 다른 방에 있는 거예요. 반대로 섞여서 꼬일 일도 없고요.

그래서 실무 규칙은 세 가지로 정했어요. 한 일은 한 창구에서 끝내기, 같은 지시를 양쪽에 보내지 않기(두 번 실행되고 구독 한도도 두 번 씁니다), 주제가 바뀌면 /new로 끊기. 두 세션 사이에 뭔가 넘겨야 하면 파일이 다리가 됩니다. 파일은 모든 세션이 같이 보니까요.

다른 업무에 적용한다면

  • 팀 슬랙에 역할별 봇을 여러 개 두고 싶을 때, 봇 계정 하나에 채널별 캐릭터 바인딩으로 해결할 수 있을 것 같아요. 이번엔 캐릭터 3명만 채널을 따로 줬는데, 더 늘려도 구조는 같습니다.
  • 어떤 AI 도구든 "설치 가이드 완료" 뒤에 규칙 위반 테스트 하나를 넣는 습관은 그대로 옮길 수 있어요.

도움이 필요한 부분

  • 슬랙 DM은 pairing 방식이라 첫 DM 때 승인이 한 번 필요한데, 아직 안 해봤어요. 이걸 팀원 여러 명에게 열 때 매번 승인해야 하는지 아시는 분 계시면 알려주세요.
  • 캐릭터 폴더에 링크로 걸어 둔 스킬이 실제로 로드되는지 아직 확인 못 했어요. 스킬 폴더의 링크 허용 옵션을 켜 두긴 했는데, 검증한 분이 계신지 궁금합니다.
